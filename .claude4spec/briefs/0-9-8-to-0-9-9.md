# Brief: 0.9.8 → 0.9.9

This release does two unrelated things. It **adds a model** — `fable-5.1` — to the alias registry of two adapters and enrolls it in the adaptive-thinking-only class. And it **substantially retracts the subagent lifecycle contract around run-level termination**: the unified `subagent_completed.status` vocabulary, the "at most once" pairing invariant, the "abort closes every open subagent" guarantee and the conformance requirement that proved it are all gone from the specification, across seven pages, with nothing added in their place. Alongside that retraction, the `codex` adapter's subagent lifecycle capability was upgraded from "none" to "synthesized".

Nothing in this release changes a function signature or a return shape, so nothing here is source-breaking. The retraction is nonetheless the more consequential half: a guarantee consumers could previously rely on is no longer written down anywhere in the spec.

## New model: `fable-5.1`

The alias registry gained one model in two adapters.

**claude-code** — new row in the models table:

| alias | resolved id | context window | adaptive-only |
|-------|-------------|----------------|---------------|
| `fable-5.1` | `claude-fable-5-1` | 1,000,000 | ✓ |

**opencode-openrouter** — new row in the models table:

| alias | resolved id | context window |
|-------|-------------|----------------|
| `claude-fable-5.1` | `anthropic/claude-fable-5.1` | 1,000,000 |

Note the two aliases are spelled differently per adapter (`fable-5.1` vs `claude-fable-5.1`) while both resolve to a 1M-token model; the OpenRouter id carries the `anthropic/` vendor prefix.

The resolved id `claude-fable-5-1` also joins the `ADAPTIVE_THINKING_ONLY` set, whose membership is now exactly:

```
claude-fable-5-1
claude-fable-5
claude-sonnet-5
claude-opus-4-6
claude-opus-4-7
claude-opus-4-8
claude-opus-5
```

For every id in that set the adapter **must not push a fixed thinking budget** — these models use native adaptive thinking only.

This change is purely additive: no alias was removed or renamed, and no default model changed.

## `codex` now synthesizes subagent lifecycle events

In M06's capability/degradation matrix (L2), the `codex` column of the **"Lifecycle events"** row moved:

- before: `❌ no subagent concept`
- after: `⚠️ synthesized`

The accompanying degradation note changed to match. Previously it read that "codex has no subagent concept, so `subagentTaskId` is never populated and **no lifecycle events are produced**"; it now ends "…and **lifecycle is at best synthesized**." So `subagentTaskId` is still never populated on codex, but consumers should now expect synthesized `subagent_started` / `subagent_completed` events from that adapter where previously they were guaranteed to see none. Code that treated "zero subagent events" as a codex invariant needs to stop doing so.

## The run-level-termination subagent guarantee was withdrawn

This is the largest movement in the release and it is a **removal**. In 0.9.8 the spec stated that when a run ends by `abort()`, `timeoutMs`, or hold-cap expiry with subagents still in flight, every open subagent lifecycle pair is closed before the stream ends. In 0.9.9 that statement does not appear on any page.

Several subagent readings of the diff assumed the content had been relocated — most plausibly to M13, which M06 used to name as the owner. It was not: **M13 is not among the eight pages this release touched.** The content was deleted, not moved.

Concretely, the following disappeared.

**The unified status vocabulary (M06, Unified Contract / L1).** The paragraph defining `subagent_completed.status` is gone. It had declared the closed set:

```
'completed' | 'failed' | 'aborted' | 'stopped'
```

where `'aborted'` meant "closed by run-level termination" and `'stopped'` meant "per-task stop control". With it went the adapter mapping rule — that adapters map SDK spellings onto these names, that an unrecognized but *cancellation-shaped* value maps to `'aborted'`, that an unrecognized and unshaped value maps to `'failed'` and emits one `warning` per run, and that an adapter must **never** map an unknown value to `'completed'`. Also removed from the same section: the rule **"at most one `subagent_completed` per `subagent_started`"**.

**The pairing invariants (M06, Testing & Conformance / L5).** The entire L5 section was deleted, taking both invariants with it: *Lifecycle pairing* (every `subagent_started` is matched by a `subagent_completed` before the stream ends, on every terminal path including abort, timeout and hold-cap) and *At most once* (no `subagent_started` is matched by two `subagent_completed`). M06 no longer carries any conformance commitment at all — the index's Modules table row for M06 moved from layers `L1, L2, L4, L5` to `L1, L2, L4`, and its dependency row naming M13 as owner of the termination contract was deleted too. The "Lifecycle closed on run-level termination" row was also dropped from M06's capability matrix, so there is no longer a per-adapter answer to that question.

**The conformance requirement that proved it (M12, e2e scenario catalog / L5).** The `abort` scenario requirement was narrowed:

- before: `abort()` mid-stream ends the run cleanly (`AdapterAbortError`, channel closed); **and, with a subagent in flight, the lifecycle family is closed before the stream ends rather than left as an unmatched `subagent_started`**
- after: `abort()` mid-stream ends the run cleanly (`AdapterAbortError`, channel closed)

Adapter e2e suites are therefore no longer required by the catalog to exercise "abort with a subagent in flight".

**The cap-expiry asymmetry (M17, Edge cases).** The hard timeout on a held control channel previously distinguished two outcomes; now it states one. Before, any remaining **background** task was abandoned with its completion never reported, while open **subagents** were the other half of the asymmetry and were *closed rather than abandoned* — "a subagent ends with the run, so the adapter can report its end honestly where it cannot report a background task's". After, the text reads simply that "any remaining task is abandoned with its completion never to be reported." The subagent carve-out is gone.

**The per-adapter mechanics (A01 claude-code, A03 opencode, A04 gemini).** Each adapter page lost its own narration of how it satisfied the guarantee:

- *claude-code* dropped the description of walking its in-flight task-id set on run-level termination and emitting `subagent_completed` (`status: 'aborted'`) for each before the stream ends — including the warning that the `Map<task_id, task_type>` is *not* that set, because it never removes entries and walking it would re-close every subagent the run ever started. It also dropped the note that `task_notification.status` is a closed union (`completed` / `failed` / `stopped`), that `Query.stopTask()` is unused so no adapter call currently produces `'stopped'`, the schema-drift warning that `task_updated.patch.status` already carries the wider `cancelled` / `canceled` vocabulary, and the defensive-read rule mapping an unrecognized `task_notification.status` onto `'aborted'` or `'failed'` with a one-time `warning`.
- *opencode* dropped the explanation that the tracked `subagentTaskId` is closed with a synthesized `subagent_completed` (`status: 'aborted'`) before the stream ends, and that ordering-based attribution under a single-active assumption closes exactly the one subagent being tracked.
- *gemini* dropped both its `agent_end` reason mapping (`'failed'` → `'failed'`, `'aborted'` → `'aborted'`, otherwise `'completed'` — native, so the abort case is reported rather than inferred) and the abort backstop that closed each thread still in the active set without double-closing one that already received its own `agent_end`.

### One point of tension worth resolving before you act on this

The removals above read as a contract being withdrawn, but one change in the same release points the other way: on the claude-code page the `abort` row of the **e2e coverage table (L5)** flipped from

```
⚠️ partial — abort mid-stream is covered; the subagent leg (a run-level termination
with a subagent in flight closes the lifecycle pair, exactly once) is not implemented yet
```

to `✅ covered`.

So claude-code now reports the subagent-abort leg as fully covered in exactly the release where the requirement it satisfies was deleted from the shared catalog and the invariant was deleted from M06. Both readings are consistent with the diff — "the behaviour shipped and the redundant narration was retired" and "the cross-cutting guarantee was dropped to a per-adapter concern" — and the eight changed pages do not settle which. Treat the guarantee as **unspecified** rather than as either promised or removed, and confirm intent (`c4s ask`, or with the spec author) before deleting or relaxing any implementation that currently closes subagent pairs on abort.

## Release policy: the semver rule for new vocabulary values was removed

M12's Public API & Packaging (L4) section lost this bullet outright, with no replacement:

> **Value-level additions.** A new **value** of an existing declared vocabulary is additive and therefore minor, on the same footing as a new event or param. Where the field is typed loosely enough that a consumer's exhaustive `switch` gets no compiler warning, the behavioral CHANGELOG note above is not optional — it is the consumer's only signal.

The surrounding "Semver", "Behavioral-hardening note" and "Worked case — M18 tool gating" bullets are unchanged. There is now no stated rule for how adding a new value to an existing enum-like field is versioned, and no stated obligation to write a behavioral CHANGELOG note when the new value would slip past a consumer's exhaustive `switch`. No CI gate, script or automated conformance check was added or removed — this is a written policy change only.

## For implementers

Ordered so that the additive work, which is unambiguous, comes before the work that needs a decision.

1. **Register the claude-code alias.** Add `fable-5.1` → `claude-fable-5-1` to the claude-code model/alias table, context window `1000000`. (M02 / claude-code adapter A01.)
2. **Register the opencode-openrouter alias.** Add `claude-fable-5.1` → `anthropic/claude-fable-5.1`, context window `1000000`. Keep the alias spelling distinct from the claude-code one — they are not the same string. (M02 / opencode adapter A03.)
3. **Extend the `ADAPTIVE_THINKING_ONLY` constant** with the resolved id `claude-fable-5-1`. Final membership is `claude-fable-5-1`, `claude-fable-5`, `claude-sonnet-5`, `claude-opus-4-6`, `claude-opus-4-7`, `claude-opus-4-8`, `claude-opus-5`. Verify the thinking-budget path: for any id in this set the adapter must send no fixed thinking budget and rely on native adaptive thinking.
4. **Add coverage for the new aliases** in whatever test asserts alias→id resolution per adapter, and one assertion that `claude-fable-5-1` takes the adaptive-only branch rather than the fixed-budget branch.
5. **Codex subagent lifecycle.** Where codex currently emits no subagent events, it must now be able to emit synthesized `subagent_started` / `subagent_completed`. `subagentTaskId` stays unpopulated on this adapter. Audit any consumer or test asserting "codex produces zero subagent events" — that assertion is no longer valid. (M06 / L2.)
6. **Do not delete existing abort-time subagent-closure code yet.** claude-code's in-flight task-id walk, opencode's `subagentTaskId` flush, and gemini's `agent_end` backstop are all still in the codebase and are no longer described by the spec. See the tension section above: resolve intent first. If the intent turns out to be "keep the behaviour, stop restating it per adapter", the code stays as is and only the pages changed.
7. **If the guarantee is confirmed as withdrawn**, then and only then: drop the "abort with subagent in flight" assertion from adapter e2e suites (the `abort` scenario now only has to prove `AdapterAbortError` plus a closed channel), and stop treating `subagent_completed.status` as a closed set of `'completed' | 'failed' | 'aborted' | 'stopped'` — no page declares that vocabulary any more, so any exhaustive `switch` over it needs a default branch.
8. **Release process.** When you next add a value to an existing vocabulary field, note that the rule classifying that as a minor bump — and requiring a behavioral CHANGELOG entry when consumers get no compiler warning — is no longer in the spec. Decide it explicitly for the release rather than assuming the old rule still holds.
