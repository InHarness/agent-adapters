# Brief: 0.0.5 → 0.0.6

Newer Claude models ship task-tracking not as the single `TodoWrite` tool but as a per-item CRUD family (`TaskCreate` / `TaskGet` / `TaskUpdate` / `TaskList`) reached through a `ToolSearch` discovery gate. This release hardens the `claude-code` adapter so that rename does not silently break two behaviors: projecting task state into the unified `todo_list_updated` event, and keeping a usable task tool available in plan mode. Nothing else in the system changes — the fix is entirely inside the `claude-code` adapter (A01), and the unified event contract (`todo_list_updated`, owned by M01) is unchanged.

## What changed

**1. Task-tracking projection is now source-agnostic.**

Previously the adapter recognized only a `TodoWrite` `tool_use` block, projected it to a `todoList` block plus a `todo_list_updated` event, and suppressed the echoed `tool_result` as redundant. `TodoWrite` does a full-list replace.

Now the adapter recognizes the whole task-tracking family and projects any of them to the same `todoList` block + `todo_list_updated` event (with `source: model-tool`), still suppressing the echoed `tool_result`:

- Legacy `TodoWrite` → full-list-replace of the running snapshot (unchanged behavior).
- New per-item CRUD tools `TaskCreate` / `TaskGet` / `TaskUpdate` / `TaskList` → **accumulated** into the running snapshot rather than replacing it. Each per-item block updates one entry of the snapshot; the adapter emits `todo_list_updated` from the accumulated snapshot.

The `todo_list_updated` event itself stays source-agnostic and owned by M01, so this projection is rename-durable regardless of which alias the SDK ships.

**2. Plan-mode read-only allowlist tracks every current alias.**

The adapter hides mutating built-ins in plan mode via `tools` / `disallowedTools` (not the SDK's `permissionMode: 'plan'`, so consumer-curated MCP tools still execute). The rule is now stated as a behavioral invariant rather than a frozen tool list:

> The read-only allowlist must track *every current alias* of a renamed or relocated built-in across SDK versions — the same discipline already applied to the `Task` → `Agent` rename — and must keep the task-tracking family (`TodoWrite` plus `TaskCreate` / `TaskGet` / `TaskUpdate` / `TaskList`) **plus the `ToolSearch` discovery gate** available, so a plan-mode turn on a newer model always retains a usable task-tracking tool and never silently degrades to prose-only planning.

Without `ToolSearch` in the allowlist, the CRUD tools stay undiscoverable in plan mode and the turn falls back to prose planning — the regression this release prevents.

## Acceptance criteria added (adapter A01)

Three criteria were added to the `claude-code` adapter, all observable at runtime:

- **Requirement:** In plan mode the read-only allowlist tracks every current alias of a renamed built-in (`TodoWrite` plus the `TaskCreate` / `TaskGet` / `TaskUpdate` / `TaskList` family and the `ToolSearch` discovery gate), so a plan-mode turn on a newer model always has a usable task-tracking tool and never falls back to prose planning.
- **Requirement:** The adapter projects task-tracking into `todo_list_updated` (source `model-tool`) whether the SDK emits legacy `TodoWrite` or the per-item `TaskCreate` / `TaskUpdate` CRUD family.
- **Edge case:** On a newer Claude model where task-tracking is the `TaskCreate` / `TaskUpdate` CRUD family gated behind `ToolSearch`, a plan-mode turn still surfaces a usable task tool and still projects `todo_list_updated` — no regression to prose-only planning.
